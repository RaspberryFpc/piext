PiExt – Raspberry Pi Backup and Restore Tools

PiExt is a backup and restore solution for Raspberry Pi systems. It consists of two applications: PiExt for Linux and PiExtRestorer for Windows.

PiExt for Linux

PiExt creates and restores compressed images of complete Raspberry Pi drives, including the MBR, boot partition and EXT2, EXT3 or EXT4 system partition. It provides a graphical user interface (GUI) and supports image creation from the command line (CLI).

PiExtRestorer for Windows

PiExtRestorer restores images created with PiExt directly under Windows. The MBR, boot partition and system partition can be selected independently. Image creation is not available in PiExtRestorer.

For system images, PiExt stores only the sectors currently used by the filesystem. The image data is compressed using Zstandard (ZSTD), reducing the amount of data that needs to be stored.

Both applications use the same PiExt image format and are distributed together in each release.

Download and Installation

Download the latest release from GitHub. Each release contains both applications:

  • Linux: piext.deb – PiExt for Raspberry Pi OS and other Debian-based systems.
  • Windows: PiExtRestorer_Setup.exe – PiExtRestorer for Windows.

Installing PiExt on Linux

Download piext.deb and install it on your Raspberry Pi: 

sudo apt install ./piext.deb

PiExt can then be started from the desktop application menu or from a terminal.

Linux – root privileges required: PiExt must be started with root privileges for operations that directly access drives and partitions. Start it from a terminal with: 
sudo piext

Installing PiExtRestorer on Windows

Download PiExtRestorer_Setup.exe from the GitHub Releases page and run the installer. Start PiExtRestorer using Run as administrator so that it can access physical drives and partitions.

Graphical User Interfaces

PiExt provides a graphical interface for selecting the source drive for a backup, the target drive for a restore and the folder used to store the images. PiExtRestorer provides the corresponding restoration interface under Windows.

PiExt works with complete drives rather than requiring the user to manually select individual partitions for a complete backup.

Drive Structure and Supported Partitioning

A typical Raspberry Pi system drive contains a boot partition and a Linux system partition. PiExt stores the MBR, boot partition and system partition as separate image components.

Depending on the device, partition names can differ. For example, normal drives use names such as /dev/sda1 and /dev/sda2, while SD cards and NVMe drives may use names such as /dev/mmcblk0p1 or /dev/nvme0n1p1.

Partition table support: PiExt and PiExtRestorer support drives using an MBR partition table. GPT-partitioned drives are not supported.

Creating a Backup with PiExt

Select the complete source drive in PiExt and specify the directory where the images should be stored. PiExt creates or updates the MBR and boot images and creates a system image.

A complete Raspberry Pi backup consists of separate image components:

  • MBR image
  • compressed boot partition image
  • compressed EXT2, EXT3 or EXT4 system image

The system image contains only the sectors currently used by the filesystem. This can make it considerably smaller than a raw image of the complete partition.

Base Image

The first system backup stored in an image directory becomes the Base Image. It contains the used filesystem data required as the starting point for restoring the system partition.

Differential Images

Subsequent system backups can be stored as Differential Images. Each Differential Image is created directly from the Base Image and contains the differences relative to that Base Image.

Differential Images are not chained together. Each Differential Image therefore remains directly associated with the Base Image and can be restored without any other Differential Images.

Image Types

PiExt uses different image formats for the different parts of a drive:

  • MBR image: contains the saved MBR and partition table.
  • Boot image: complete compressed image of the boot partition.
  • System image: filesystem-aware image of the used sectors of an EXT2, EXT3 or EXT4 system partition.

Boot and system images use Zstandard (ZSTD) compression. MBR images are stored separately as .img files.

Restoring a Backup

Images can be restored with PiExt under Linux or PiExtRestorer under Windows. In both applications, the MBR, boot partition and system partition can be selected independently. Only the selected components are restored.

A Base Image or Differential Image must be selected before starting a restore, even when restoring only the MBR or only the boot partition.

When restoring a Differential Image, the corresponding Base Image must also be available. The selected Differential Image is applied directly to that Base Image; no other Differential Images are required.

PiExt can also restore an image to a completely empty drive. The target drive does not need to contain an existing partition table before restoration.

Restoring the MBR writes the saved partition table to the target drive. This can change the target drive's partition layout and may affect access to other partitions.

Command Line Interface

PiExt for Linux can also be used without the graphical interface. The CLI supports automated image creation and is useful for scripts and scheduled backups. Image restoration is performed through the GUI.

For example:

sudo piext /dev/sda /backup/piext

An SD card can be specified in the same way:

sudo piext /dev/mmcblk0 /backup/piext

Active Root Partition

Under Linux, the currently running root partition cannot be restored while the system is running from that partition. To restore the active system partition, boot the Raspberry Pi from another system or boot medium first.

Alternatively, use PiExtRestorer under Windows to restore the system partition without booting the Raspberry Pi from another Linux system.

Compatibility

PiExt is designed for Raspberry Pi systems running Linux. It supports common storage devices including SD cards, USB drives and NVMe drives, provided that the drive uses an MBR partition table.

EXT2, EXT3 and EXT4 system partitions are supported for filesystem-aware system backups. PiExtRestorer runs under Windows and restores images created by PiExt.

Typical Backup Workflow

  1. Start PiExt with sudo.
  2. Select the complete source drive.
  3. Select or create the image directory.
  4. Create the backup.
  5. The first system image in the directory becomes the Base Image.
  6. Later system backups can be stored as Differential Images.

Typical Restore Workflow

  1. Start PiExt with root privileges under Linux or PiExtRestorer as administrator under Windows.
  2. Select the complete target drive.
  3. Select a Base Image or the required Differential Image.
  4. Select one or more restore components: MBR, boot partition and/or system partition.
  5. Check the selected target drive and start the restore.
  6. Reboot the Raspberry Pi after the restore is complete.

Requirements

PiExt for Linux

  • Raspberry Pi system running Linux
  • MBR-partitioned drive (GPT is not supported)
  • Root privileges for direct drive access
  • EXT2, EXT3 or EXT4 for filesystem-aware system images
  • Storage device containing the backup images when restoring

PiExtRestorer for Windows

  • Windows operating system
  • Administrator privileges for direct drive access
  • Access to the folder containing the PiExt image files
  • MBR-partitioned target drive (GPT is not supported)

Project
