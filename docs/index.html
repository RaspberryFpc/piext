PiExt

Deutsche Dokumentation

PiExt is a backup and restore application for Raspberry Pi systems that can be used either through its graphical user interface (GUI) or from the command line (CLI).

It creates and restores compressed images of Linux EXT2, EXT3 and EXT4 partitions.

Instead of storing the complete partition, PiExt stores only the sectors currently in use by the filesystem and compresses the data on the fly using Zstandard (ZSTD).

The first image created in an image folder is automatically created as a Base Image. Further images are created as Differential Images directly based on the Base Image.

Download & Installation

The latest version of PiExt can be downloaded from GitHub Releases or SourceForge.

  • GitHub Releases
  • SourceForge

Installation

Download the latest .deb package and open a terminal in the directory containing the downloaded file.

Install PiExt using: 

sudo apt install ./piext.deb

The package manager automatically installs any required dependencies.

After installation, PiExt can be started either from the desktop application menu using the graphical user interface or from a terminal using the command piext.

Graphical User Interface (GUI)

When PiExt is started without command-line parameters, it starts in GUI mode.

The graphical user interface can be used to select the Source Partition, Target Partition, image folder and other settings and to start image creation or restoration interactively.

Command-Line Interface (CLI)

PiExt can also be operated completely from the command line. When one or more command-line parameters are specified, PiExt automatically operates in CLI mode.

In CLI mode, the graphical user interface is not displayed. The requested operation can therefore be performed without user interaction through the GUI.

After the operation has completed, PiExt automatically exits and returns an exit code to the operating system.

Command-line parameters can be specified either using = or separated from the value by a space.

Examples:

--sourcepartition=/dev/sda2

or:

--sourcepartition /dev/sda2

Create an Image

Parameter Description
--create Automatically starts image creation.
--sourcepartition <partition> Specifies the Source Partition from which the image is created, for example /dev/sda2.
--createdestination <folder> Specifies the destination folder for the image. If the folder does not exist, it is created automatically.
--destination <folder> Specifies the destination folder for the image. The folder must already exist.
--compressionlevel <value> Sets the Zstandard compression level.
--lastsettings Uses the last saved PiExt settings as the initial values. Explicitly specified command-line parameters override these settings.

Restore an Image

Parameter Description
--restore Automatically starts image restoration.
--sourceimage <file> Specifies the image file to be restored.
--targetpartition <partition> Specifies the Target Partition to which the image is restored, for example /dev/sda2.

General CLI Notes

--create and --restore automatically start the corresponding operation.

The difference between --createdestination and --destination is that --createdestination automatically creates a destination folder if it does not exist, whereas --destination requires the destination folder to already exist.

--lastsettings can be used together with the other parameters. Explicitly specified command-line parameters take precedence over the saved settings.

CLI Examples

Create an image and create the destination folder if necessary: 

sudo piext --create --sourcepartition /dev/sda2 --createdestination "/media/pi/hzg2/Diff_image"

Create an image using compression level 5: 

sudo piext --create --sourcepartition /dev/sda2 --createdestination "/media/pi/hzg2/Diff_image" --compressionlevel 5

Create an image using an existing destination folder: 

sudo piext --create --sourcepartition /dev/sda2 --destination "/media/pi/hzg2/Diff_image"

Restore an image: 

sudo piext --restore --sourceimage "/media/pi/hzg2/Diff_image/base_image_sda2_2026-09-21.zst" --targetpartition /dev/sdd2

Use the saved settings and automatically start image creation: 

sudo piext --lastsettings --create

CLI Exit Codes

In CLI mode, PiExt automatically exits after the operation has completed.

  • 0 = operation completed successfully
  • 1 = error during the operation

Source and Target Partitions

A Source Partition must be selected to create an image. The Source Partition is the EXT2, EXT3 or EXT4 partition from which the image is created.

A Target Partition must be selected to restore an image. The Target Partition is the partition to which the selected image is restored.

The image storage folder is selected independently of the Source or Target Partition.

Image Folder

PiExt uses a folder to store the image files.

To create an image, an image folder must be selected or created. To restore an image, the folder containing the required image files must be selected.

Only one Base Image is allowed per image folder. PiExt assigns the file names automatically.

Image Storage

PiExt does not store the complete partition. Only the sectors currently used by the EXT filesystem are included in the image. Unused sectors are omitted.

This significantly reduces the amount of data that must be read, processed and stored, especially on partitions with a large amount of free space.

The image data is compressed during creation using Zstandard (ZSTD). The resulting files use the .zst file extension.

Base Image

The first image created in an empty image folder automatically becomes the Base Image. It contains the initial state of the EXT partition. 

base_image_sda2_2026-09-21.zst

The file name contains the Source Partition and the creation date.

Differential Images

Every subsequent image created in the same image folder is created as a Differential Image.

A Differential Image contains the changes compared to the Base Image. Differential Images are based directly on the Base Image and do not depend on other Differential Images. 

diff-image_2026-09-21_1.zst
diff-image_2026-09-21_2.zst
diff-image_2026-09-21_3.zst

Each Differential Image can therefore be restored independently.

Restoring Images

Any image in the folder can be selected individually for restoration.

Restoring the Base Image

Only the Base Image is required to restore the Base Image. 

base_image_sda2_2026-09-21.zst

Restoring a Differential Image

When a Differential Image is selected, the corresponding Base Image must also be present in the same image folder. 

base_image_sda2_2026-09-21.zst
diff-image_2026-09-21_1.zst

The restoration process combines the Base Image with the selected Differential Image: 

Base Image + Diff Image 1 → restored partition

Other Differential Images are not required for the restoration and can be deleted if they are no longer needed.

Image Structure

Base Image
     |
     +-- Diff Image 1
     +-- Diff Image 2
     +-- Diff Image 3

Each Differential Image uses the same Base Image. The Base Image must remain available as long as the corresponding Differential Images are still needed.

Image Compatibility

PiExt uses its own application-specific image format.

Images created with PiExt can currently only be restored using PiExt.

The .zst files are not standard disk images and cannot be written directly to a device using tools such as dd.

Typical Workflow

Creating Images

  1. Select the Source Partition.
  2. Select or create the image folder.
  3. Create the first image.
  4. The first image automatically becomes the Base Image.
  5. Make changes to the system.
  6. Create another image.
  7. The new image is automatically created as a Differential Image.
  8. Repeat the process as needed.
  9. Delete Differential Images that are no longer needed.

Restoring an Image

  1. Select the Target Partition.
  2. Select the image folder containing the images.
  3. Select the desired image.
  4. Start the restoration.
  5. When restoring a Differential Image, the Base Image must also be present in the image folder.

The selected image is restored directly to the Target Partition.

Restoring the Active Root Partition

The currently running Root Partition cannot be restored while the system is running from that partition.

To restore the active Root Partition, the Raspberry Pi must first be booted from another system or boot medium.

A recommended solution is a separate SD card or USB flash drive with a minimal Linux system and a minimal desktop environment on which PiExt is installed.

Boot the Raspberry Pi from this SD card or USB flash drive and run PiExt from the separate system. The original system partition is then no longer the active Root Partition and can be restored.

The image files can be stored on another USB drive, network storage, or any other accessible storage medium.

After the restoration is complete, shut down the Raspberry Pi and then boot it again from the restored system.

Requirements

  • Linux
  • Raspberry Pi system
  • EXT2, EXT3 or EXT4 Source/Target Partitions
  • Zstandard (ZSTD)
  • Appropriate permissions to access the Source and Target Partitions
  • A graphical desktop environment for the PiExt GUI
  • A terminal for using the PiExt CLI
