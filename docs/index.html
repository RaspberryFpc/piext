PiExt

Deutsche Dokumentation

PiExt is a backup and restore application for Raspberry Pi systems. It can be used through its graphical user interface (GUI) or directly from the command line (CLI).

PiExt works with complete drives and creates a backup consisting of the MBR, boot partition and system partition.

The system partition is designed for Linux EXT2, EXT3 and EXT4 filesystems. PiExt stores the filesystem data required for the image and compresses it during creation using Zstandard (ZSTD).

The first image created in an image folder becomes the Base Image. Further backups can be created as Differential Images directly based on the Base Image.

Download & Installation

The latest version of PiExt can be downloaded from GitHub Releases or SourceForge.

  • GitHub Releases
  • SourceForge

Installation

Download the latest .deb package and open a terminal in the directory containing the downloaded file.

Install PiExt using: 

sudo apt install ./piext.deb

The package manager automatically installs any required dependencies.

PiExt requires root privileges. Therefore PiExt must always be started using sudo.

Start the graphical interface with: 

sudo piext

Graphical User Interface (GUI)

When PiExt is started without command-line parameters, it starts in GUI mode.

The GUI allows you to select a complete source drive and an image folder. PiExt automatically determines the boot and system partitions of the selected drive.

The GUI can be used to create backups and restore individual parts of a backup.

Drive Structure

PiExt works with a complete drive rather than selecting a single source partition for backup.

A typical Raspberry Pi drive contains: 

Drive
├── MBR
├── Partition 1 → Boot
└── Partition 2 → System

PiExt handles these parts separately:

  • MBR – stored as a separate image file
  • Boot partition – stored as a complete compressed image
  • System partition – stored using PiExt's filesystem-aware image format

Creating a Backup

Select a complete drive in the GUI and select the folder in which the images should be stored.

When the first backup is created, PiExt creates the MBR image, the boot image and the Base Image of the system partition.

Example: 

backup/
├── mbr_image_2026-09-28.img
├── boot_image_2026-09-28.zst
└── base_image_sda_2026-09-28.zst

The file names are assigned automatically by PiExt.

Base Image

The first system image created in an image folder automatically becomes the Base Image. 

base_image_sda_2026-09-28.zst

Only one Base Image is allowed in an image folder.

The Base Image is the reference for all subsequent Differential Images in that folder.

Differential Images

When a Base Image already exists in the image folder, a subsequent backup creates a Differential Image. 

base_image_sda_2026-09-28.zst
diff-image_2026-09-29_1.zst
diff-image_2026-09-30_2.zst
diff-image_2026-10-01_3.zst

Every Differential Image is based directly on the Base Image. Differential Images do not form a chain. 

Base Image
    ├── Diff Image 1
    ├── Diff Image 2
    └── Diff Image 3

This means that a Differential Image does not depend on any other Differential Image.

The Base Image must remain available as long as its Differential Images are needed for restoration.

Image Types

MBR

The MBR is stored separately as an uncompressed .img file. 

mbr_image_2026-09-28.img

The MBR is intentionally not compressed because it is very small.

Boot Partition

The boot partition is stored as a complete compressed image. 

boot_image_2026-09-28.zst

System Partition

The system partition is handled using PiExt's filesystem-aware image format for EXT2, EXT3 and EXT4.

The image data is compressed during creation using Zstandard. The resulting files use the .zst extension.

Restoring a Backup

PiExt can restore the individual parts of a backup independently:

  • MBR
  • Boot partition
  • System partition

This makes it possible, for example, to restore only the system partition without overwriting the MBR or boot partition.

When restoring a Differential Image, the corresponding Base Image must also be available in the same image folder.

The selected Differential Image is combined with the Base Image during the restore process.

Restoring the Base Image

To restore the Base Image, the Base Image itself is required. 

base_image_sda_2026-09-28.zst

Restoring a Differential Image

To restore a Differential Image, the Base Image and the selected Differential Image must be available. 

base_image_sda_2026-09-28.zst
diff-image_2026-09-29_1.zst

Other Differential Images are not required.

Command-Line Interface (CLI)

PiExt can also be operated without displaying the graphical interface.

The CLI has been deliberately kept simple. It requires only the source drive and the destination folder. 

sudo piext <drive> <destination-folder>

Example: 

sudo piext /dev/sda /backup/piext

For an SD card: 

sudo piext /dev/mmcblk0 /backup/piext

The destination folder is created automatically if it does not exist.

In CLI mode:

  • PiExt requires root privileges.
  • The graphical interface is not displayed.
  • The backup starts automatically.
  • The destination folder is created automatically if necessary.
  • PiExt exits automatically after the operation has completed.

CLI Exit Codes

  • 0 = backup completed successfully
  • 1 = error during the backup

Restoring the Active Root Partition

The currently running Root Partition cannot be restored while it is mounted as /.

To restore the active system partition, the Raspberry Pi must first be booted from another Linux system or another boot medium.

A practical solution is a separate SD card or USB drive containing a minimal Linux system and a minimal desktop environment with PiExt installed.

Boot the Raspberry Pi from this separate system and start PiExt with: 

sudo piext

The original system partition is then no longer the active Root Partition and can be restored.

After the restoration has completed, shut down the Raspberry Pi and boot it again from the restored drive.

Image Compatibility

PiExt uses its own application-specific image format.

PiExt images can currently only be restored using PiExt.

The .zst files are not standard complete disk images and cannot simply be written to a drive using tools such as dd.

Important

  • PiExt must always be started with sudo.
  • PiExt works with complete drives.
  • The first backup in an image folder creates the Base Image.
  • Only one Base Image is allowed per image folder.
  • Subsequent backups create Differential Images.
  • Differential Images are based directly on the Base Image.
  • The Base Image must remain available for Differential Image restoration.
  • The MBR is stored separately as an uncompressed image.
  • The boot partition is stored as a complete compressed image.
  • The system partition uses PiExt's filesystem-aware image format.
  • Images can currently only be restored using PiExt.
  • Always verify the selected source and target drive before starting a backup or restore.
  • Restoring data can overwrite existing data on the target drive.

Typical Backup Workflow

  1. Start PiExt with sudo piext.
  2. Select the complete source drive.
  3. Select or create the image folder.
  4. Create the first backup.
  5. The first backup becomes the Base Image.
  6. Make changes to the Raspberry Pi system.
  7. Create another backup.
  8. PiExt automatically creates a Differential Image.
  9. Repeat the process as required.

Typical Restore Workflow

  1. Start PiExt with sudo piext.
  2. Select the target drive.
  3. Select the image folder.
  4. Select the required image.
  5. Select which parts should be restored: MBR, Boot and/or System.
  6. Confirm the restore operation.
  7. PiExt restores the selected parts.

Requirements

  • Linux
  • Raspberry Pi
  • EXT2, EXT3 or EXT4 system partitions
  • Zstandard (ZSTD)
  • Root privileges
  • A graphical desktop environment for using the GUI
  • A terminal for using the CLI
