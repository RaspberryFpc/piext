Overview

PiExt is a tool for creating and restoring Raspberry Pi backups. It does not image the entire drive; it focuses on the components essential to the system.

PiExt supports image creation and restoration under Linux. The separate PiExtRestorer application provides image restoration under Windows. Both applications are distributed together in a single release package.

Run with administrator privileges: PiExt must always be started with sudo to access physical drives and partitions directly.

Backup scope

MBR The first sector of the drive, including MBR boot code and the partition table.
Boot partition The complete boot partition.
System partition The EXT-based Linux system partition. Only filesystem areas currently in use are stored.
Other partitions They are outside the image scope and are preserved during restoration whenever possible.

Expected Raspberry Pi partition layout:

  1. Partition 1: Boot partition
  2. Partition 2: System partition

PiExt uses complete physical drives as source and target references, but only backs up and restores the MBR, boot partition and system partition.

Creating images

Use the graphical interface to select the source drive and destination folder. PiExt automatically creates or updates the MBR and boot images during every image creation operation.

  • The previous MBR image is replaced.
  • The previous boot image is replaced.
  • An existing Base Image and existing Differential Images remain unchanged.
  • The system image is created as a Base Image or as a new Differential Image, depending on the contents of the image folder.
Important: The source drive and backup destination should be on different physical drives. This helps prevent backup data from overwriting the source system.

ZSTD compression

Boot, Base and Differential Images are compressed using Zstandard (ZSTD). The compression level can be configured in the application settings from 1 to 19.

Level Effect
1 Fast compression, producing larger image files.
2–8 Intermediate trade-off between speed and file size.
19 Very slow compression, producing smallest image file.

A higher level may reduce the file size but takes more time. This setting affects image creation; no separate compression-level setting is required for restoration. The MBR image is stored uncompressed as an .img file.

Image types and filenames

MBR Image

mbr_image_YYYY-MM-DD.img

Contains the MBR, including the partition table, and is stored uncompressed.

Boot Image

boot_image_YYYY-MM-DD.zst

Contains the complete boot partition and is compressed using ZSTD.

Base Image

base_image_<drive>_YYYY-MM-DD.zst
Example: base_image_sda_2026-09-28.zst

Contains the initial system partition image. The first system image created in an image folder is always the Base Image. It serves as the reference for all subsequent Differential Images and is not overwritten.

Differential Image

diff-image_YYYY-MM-DD_<number>.zst
Example: diff-image_2026-09-29_1.zst

Contains changes relative to the original Base Image. Each Differential Image is based directly on that Base Image, not on a previous Differential Image. Other Differential Images are not required to restore a selected Differential Image.

Image folder structure

Image Folder/
|-- mbr_image_2026-11-05.img
|-- boot_image_2026-11-05.zst
|-- base_image_sda_2026-09-28.zst
|-- diff-image_2026-09-29_1.zst
`-- diff-image_2026-11-05_2.zst

The MBR and boot filenames show the date of the latest image creation. Base and Differential Images retain their original filenames and creation dates.

Restoring images

Restoration is performed through the graphical interface of PiExt under Linux or PiExtRestorer under Windows. The MBR, boot partition and system partition can be selected independently.

Image selection is always required: A Base Image or Differential Image must be selected before every restoration. This also applies when restoring only the MBR or only the boot partition. Only the components actually selected are restored.

Restoring a Base Image

Select the required Base Image. The MBR image and boot image are only needed if the corresponding components are selected for restoration.

Restoring a Differential Image

Select the Base Image belonging to the Differential Image and the required Differential Image. If the system partition is also being restored, both files are required. The current MBR and boot image files are only needed if those components are selected. No other Differential Images are required.

Restoring the active system partition

A running Linux system cannot restore its own active root partition. To restore the system partition under Linux, first boot the Raspberry Pi from another system or boot medium. Alternatively, use PiExtRestorer under Windows.

MBR restoration warning

Restoring the MBR also writes the saved partition table. This can change the partition layout of the target drive and may affect other partitions.

Command line

The command-line interface supports image creation only. PiExt must be run with root privileges.

Syntax

sudo piext <drive> <destination-folder>

Example

sudo piext /dev/sda /media/pi/backup
  • <drive>: complete physical source drive, for example /dev/sda.
  • <destination-folder>: folder for the image files. It is created automatically if it does not exist.

Exactly two parameters must be supplied. Image restoration is not available through the command line. The compression level and saved GUI settings cannot be configured through the CLI either.

Return codes: 0 = success, 1 = error.

Compatibility and requirements

  • Raspberry Pi running Linux for PiExt.
  • MBR partition table; GPT is not supported.
  • EXT2, EXT3 or EXT4 system filesystem.
  • Root privileges for direct access to physical drives.
  • Sufficient storage space for image files.

PiExt system images use a program-specific format and cannot be restored directly with standard tools such as dd.

PiExtRestorer requires Windows and administrator privileges to restore drives.

Important notes

  • Carefully check the source and target drives before every operation.
  • The source drive and backup destination should be different physical drives.
  • Restoration overwrites the data belonging to each selected component on the target drive.
  • Other partitions are preserved whenever possible, but this cannot be guaranteed in every situation.
  • Keep the Base Image together with its corresponding Differential Images.
  • The MBR and boot images are updated during every image creation operation.
  • Restoring the MBR also writes the saved partition table.
  • PiExt must be started with sudo.
  • A Base Image or Differential Image must be selected even when restoring only the MBR or boot partition.
Recommendation: Keep an additional copy of important backups on another storage device.
