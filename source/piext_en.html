PiExt

PiExt creates and restores compressed images of Linux EXT2, EXT3 and EXT4 partitions.

The first image created in an image folder is automatically a Base Image. Further images are created as Differential Images based on this Base Image.

Source and Target Partitions

For image creation, a Source Partition must be selected.

The Source Partition is the EXT2, EXT3 or EXT4 partition from which the image is created.

For image restoration, a Target Partition must be selected.

The Target Partition is the partition to which the selected image is restored.

The image storage folder is selected separately from the Source or Target Partition.

Image Folder

PiExt uses a folder to store the image files.

For image creation, an image folder must be selected or created.

For image restoration, the folder containing the required image files must be selected.

Only one Base Image is allowed per image folder.

PiExt automatically assigns the image filenames. No filename needs to be entered manually.

Image Storage

PiExt does not store the complete partition.

Only used sectors of the EXT filesystem are stored. Unused sectors are omitted from the image.

This significantly reduces the amount of data that needs to be stored and processed, especially when the partition contains a large amount of free space.

All images are compressed on the fly using Zstandard (ZSTD) while they are being created.

The resulting image files use the .zst file extension.

Base Image

The first image created in an empty image folder is automatically created as a Base Image.

The Base Image contains the initial state of the EXT partition.

Example:

base_image_sda2_2026-09-21.zst

The filename contains the source partition and the creation date.

Differential Images

Every additional image created in the same image folder is automatically created as a Differential Image.

A Differential Image contains the changes relative to the Base Image.

Examples:

diff-image_2026-09-21_1.zst
diff-image_2026-09-21_2.zst

The number is automatically increased for each new Differential Image.

Differential Images are based directly on the Base Image and do not depend on other Differential Images.

Restoring Images

Every image in the folder can be selected individually for restoration.

Restoring the Base Image

When the Base Image is selected, only the Base Image is required. 

base_image_sda2_2026-09-21.zst

Restoring a Differential Image

When a Differential Image is selected, the corresponding Base Image must also be available in the same image folder.

For example:

base_image_sda2_2026-09-21.zst
diff-image_2026-09-21_1.zst

The restore operation combines the Base Image with the selected Differential Image. 

Base Image + Diff Image 1 → restored partition

The other Differential Images are not required for the restore. They can be deleted if they are no longer needed.

Each Differential Image can therefore be selected and restored independently.

Image Structure

An image folder can contain: 

base_image_sda2_2026-09-21.zst
diff-image_2026-09-21_1.zst
diff-image_2026-09-21_2.zst
diff-image_2026-09-21_3.zst

The structure is: 

Base Image
     |
     +-- Diff Image 1
     +-- Diff Image 2
     +-- Diff Image 3

Each Differential Image uses the same Base Image.

Individual Differential Images can be deleted if they are no longer required.

The Base Image must remain available for all Differential Images that are still to be restored.

Image Compatibility

The image format used by PiExt is a program-specific format.

At present, images created by PiExt can only be restored using PiExt.

The .zst files should therefore not be treated as standard disk images that can be written directly to a device with tools such as dd.

  • The first image in an empty folder is automatically the Base Image.
  • Only one Base Image is allowed per image folder.
  • All subsequent images are Differential Images.

Typical Workflow

Create Images

  1. Select the Source Partition.
  2. Select or create the image folder.
  3. Create the first image.
  4. The first image automatically becomes the Base Image.
  5. Make changes to the system.
  6. Create another image.
  7. The new image is automatically created as a Differential Image.
  8. Repeat as required.
  9. Delete Differential Images that are no longer needed.

Restore an Image

  1. Select the Target Partition.
  2. Select the image folder containing the images.
  3. Select the desired image.
  4. Start the restore operation.
  5. If a Differential Image is selected, the Base Image must also be present in the image folder.

The selected image is restored directly to the Target Partition.

Restoring the Active Root Partition

The currently running root partition cannot be restored while the system is running.

To restore the active root partition, boot the Raspberry Pi from another system or boot medium first.

A recommended solution is to create a separate SD card or USB stick with a minimal Linux system and a minimal desktop environment, with PiExt installed.

Boot the Raspberry Pi from this SD card or USB stick and run PiExt from the separate system. The original system partition is then no longer the active root partition and can be restored.

The image files can be stored on another USB drive, network storage, or another accessible storage device.

After the restore operation has completed, shut down the Raspberry Pi and boot it again from the restored system.

Command-Line Parameters

PiExt can also be used from the command line. As soon as at least one command-line parameter is specified, PiExt operates in CLI mode. The graphical user interface is not displayed. After the operation has completed, PiExt exits automatically.

Parameters can be specified either using = or separated from the value by a space.

Examples:

--sourcepartition=/dev/sda2

or:

--sourcepartition /dev/sda2

Create an Image

Parameter Description
--create Automatically starts image creation.
--sourcepartition <partition> Specifies the Source Partition from which the image is created, for example /dev/sda2.
--createdestination <folder> Specifies the destination folder for the image. If the folder does not exist, it is created automatically.
--destination <folder> Specifies the destination folder for the image. The folder must already exist.
--compressionlevel <value> Sets the Zstandard compression level.
--lastsettings Uses the last saved PiExt settings as the initial values. Explicitly specified command-line parameters override these settings.

Restore an Image

Parameter Description
--restore Automatically starts image restoration.
--sourceimage <file> Specifies the image file to be restored.
--targetpartition <partition> Specifies the Target Partition to which the image is restored, for example /dev/sda2.

General Notes

--create and --restore automatically start the corresponding operation.

The difference between --createdestination and --destination is that --createdestination automatically creates a destination folder if it does not exist, whereas --destination requires the destination folder to already exist.

--lastsettings can be used together with the other parameters. Explicitly specified command-line parameters take precedence over the saved settings.

Examples

Create an image and create the destination folder if necessary:

sudo piext --create --sourcepartition /dev/sda2 --createdestination "/media/pi/hzg2/Diff_image"

Create an image using compression level 5:

sudo piext --create --sourcepartition /dev/sda2 --createdestination "/media/pi/hzg2/Diff_image" --compressionlevel 5

Create an image using an existing destination folder:

sudo piext --create --sourcepartition /dev/sda2 --destination "/media/pi/hzg2/Diff_image"

Restore an image:

sudo piext --restore --sourceimage "/media/pi/hzg2/Diff_image/base_image_sda2_2026-09-21.zst" --targetpartition /dev/sdd2

Use the saved settings and automatically start image creation: 

sudo piext --lastsettings --create

Exit Codes

In CLI mode, PiExt exits automatically after the operation has completed.

  • 0 = operation completed successfully
  • 1 = error during the operation
